# 全局约束审查与优化

## 触发条件

- 用户要求「检查全局约束 / 规范 / 规则」并总结；
- 会话运行时策略变更（审批策略、文件策略切换）后重新核对约束；
- 新增工作区或技能库变更前确定适用规则。

## 约束来源（按优先级从高到低）

1. **系统层**（DSH Harness 运行时）：工具纪律、后台任务、目标工具、路径事实、运行时策略快照（文件策略/审批策略每会话动态变化——先读会话快照再判断哪些操作可用，approval never 时不得请求 escalation）。
2. **用户全局层**：`C:\Users\y1954\.dsh\AGENTS.md`（所有工作区、所有对话生效；项目级不得削弱）。
3. **工作区层**：`<工作区>\AGENTS.md`（仅可补充，不得与全局冲突）。
4. **技能层**：`C:\Users\y1954\.agents\skills\*\SKILL.md`（规则类元技能与领域技能分开归类）。

## 审查流程

1. **读取全部来源**：用 read 读两份 AGENTS.md 与相关 SKILL.md，glob 枚举技能库；系统层规则从当前会话提示中整理。
2. **分层归类**：把每条规则归入 4 层之一。
3. **诊断**：逐条对比找重复（同一规则出现在多层）与冲突（表述不一致）。
4. **定权威与合并**：系统层 > 用户全局层 > 工作区层 > 技能层；技能是 AGENTS.md 规则的「可执行流程版」，正文与 AGENTS.md 不一致时以 AGENTS.md 为准并回写技能。
5. **产出**：统一约束清单（合并去重版）+ 落地建议（指明改哪些文件、怎么改）。
6. **落地边界**：修改用户全局规范（`~/.dsh/AGENTS.md`）影响所有会话，先给建议清单、与用户确认后再执行；技能库与工作区文件可按规则直接执行。

## 注意事项

- 系统层规则不可改，只可记录。
- 运行时策略（审批/文件策略）属于会话快照而非持久文件，总结中必须标注「动态变化，以会话快照为准」。
- 保持总结精炼：分层表 + 诊断表 + 合并后规则清单，不抄写原文。

# 技能库进化（技能提取与更新替换）

## 触发条件

- 每个多步骤任务结束前；
- 任务中发现可复用的流程、方法论、检查清单或领域知识；
- 用户要求沉淀、更新或审查技能库。

## 技能库位置

- 用户级技能根目录：`C:\Users\y1954\.agents\skills\`（所有会话共享，模型可调用）。
- 每个技能是一个目录：`<技能名>\SKILL.md`（技能名必须为 kebab-case：小写字母、数字、连字符）。
- 技能目录内可附带 `CHANGELOG.md`（版本记录）、`references\`（参考资料）、`scripts\`（脚本）。

## 提取流程

1. **回顾任务**：梳理本次任务中执行过的步骤，找出可复用于未来任务的部分。
2. **筛选**：只沉淀真正可复用、有明确操作步骤的内容（流程、规范、方法、检查清单）；一次性内容不沉淀。
3. **编写 SKILL.md**：
   - 前置元数据（YAML frontmatter）：`name`（kebab-case）、`description`（简短路由描述，写明做什么、何时用）；
   - 正文结构建议：触发条件 → 步骤/规则 → 示例 → 注意事项；
   - 正文使用简体中文，与用户全局规范一致。
4. **检查同主题技能**（按名称与 description 语义判断）：
   - **不存在** → 新增技能目录；
   - **存在且旧版本更弱**（覆盖不全、规则过时、与当前实践不符）→ **更新替换**：覆盖 SKILL.md，并在 `CHANGELOG.md` 追加版本记录（日期、版本、变更点、更新原因）；
   - **存在且范围重叠** → 合并到更合适的技能中，删除冗余技能；
   - **存在且已更优** → 不覆盖，仅补充差异到现有技能。
5. **保持精简**：技能数量少而精，职责单一；一个技能对应一类可复用能力。

## CHANGELOG 格式（更新替换时维护）

```markdown
# 更新记录

## 2026-08-21 - v1.1
- 变更点：……（如：新增 X 步骤、修正 Y 规则）
- 原因：……（如：任务 Z 中遇到旧规则不适用的情况）
```

## 注意事项

- 技能名一旦被技能库占用，同名技能以更高优先级来源为准（项目级 > 用户级），冲突时用户级技能应改名或并入项目级。
- 不写入机密信息、绝对路径之外的敏感内容；技能内容面向所有会话，应保持通用。
- 修改技能文件后，DSH 的技能目录 watcher 会自动刷新会话中的技能目录，无需重启。
